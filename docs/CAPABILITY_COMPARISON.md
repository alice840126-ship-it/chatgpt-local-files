# v0.2.0 적용 후

아래는 v0.1.0 분석 기록입니다. 이후 분할 쓰기, 문서 처리, 이미지 미리보기와 선택적 프로그램 실행을 구현했습니다. 기능 추가가 경쟁 제품보다 우월하다는 실사용 비교를 대신하지는 않습니다. GUI 설치·OCR·브라우저 자동 조작은 남아 있습니다.

# Codex 수준 접근·사용 목표와 현재 구현 비교 — 2026-10-09

결론: 독립 개발을 이어갈 이유는 변경 충돌 검사와 복구를 중심으로 한 파일 작업 흐름에 있다. 현재 제품이 Codex나 Desktop Commander보다 전체 기능에서 우월하다는 근거는 없다. OS 전체 경로 접근은 독점적 차별점이 아니다.

## 현재 확인한 범위

| 요구 | ChatGPT Local Files 현재 구현 |
|---|---|
| OS가 허용한 경로의 일반 파일·폴더 | 폴더 화이트리스트 없이 절대경로 접근. 실제 OS 권한 적용 |
| 텍스트·코드 읽기/수정 | 지원, 생성·수정 최대 8 MiB |
| 바이너리 읽기/생성 | base64, 읽기는 192 KiB 페이지. 파일 내용 이해와 별개 |
| 큰 바이너리 복사/이동 | 지원. 일반 파일 읽기는 페이지 처리하지만 매 호출 전체 파일 해시를 검사함 |
| PDF·Word·Excel 내부 내용 이해/구조 편집 | 전용 추출/편집 미지원 |
| 프로그램·Python·명령 실행과 테스트 | 실행 도구 없음 |
| 앱·브라우저 조작 | 없음 |
| 최신 변경 충돌 검사 | expected_version 필수, SHA256·객체 식별·상태 검사 |
| 이전 파일·삭제 복구 | 같은 볼륨에 보존본 유지, 현재 버전 검사 후 복구 |
| 큰 폴더·대용량 성능 | 변경 트리 최대 10,000항목. 읽기에서 전체 해시를 반복 계산하므로 큰 파일 성능 검증 필요 |

지원 대상은 일반 파일·폴더·심볼릭 링크 객체다. 장치·소켓·FIFO는 제외하며 최종 링크를 자동으로 따라가 수정하지 않는다. 작업 이력 저장 폴더와 상위 경로도 변경에서 보호한다. OS 전체 경로 접근이 권한 우회나 모든 작업 지원을 뜻하지 않는다.

실제 설치된 MCP subprocess 자체 검사에서 14개 도구와 생성·수정·읽기·오래된 버전 거부·삭제·복구가 통과했다. 다른 Mac의 권한, standalone 제품의 새 ChatGPT 등록, 경쟁 제품 실기 성능은 이번 비교에서 검증하지 않았다.

## 비교 근거

- [Desktop Commander 기능](https://github.com/wonderwhy-er/DesktopCommanderMCP): 터미널·프로세스, PDF·Word·Excel, 검색·페이지 처리 지원. 전체 기능 폭은 현재 우리 구현보다 넓다.
- [Desktop Commander 파일 코드](https://github.com/wonderwhy-er/DesktopCommanderMCP/blob/main/src/tools/filesystem.ts): `/` 또는 비어 있는 allowedDirectories는 전체 파일 경로를 허용한다. 검토한 writeFile과 moveFile 함수에 우리 expected_version과 같은 호출자 버전 인자는 없다. 이것은 검토한 경로의 차이이며 제품 전체에 보호 기능이 없다는 주장이 아니다.
- [FileMCP](https://github.com/anhnv02/file-mcp): 선택 폴더 파일 작업, Git, 선택적 명령 실행, macOS/Windows 네이티브 앱. 본인 터널·OS 자격증명 저장소 설정이 필요하다.
- [Chat2Local](https://github.com/doguozyigit/Chat2Local): 채팅별 선택 폴더, 명령·브라우저·스킬·복구 기록. README는 기록이 프로젝트 백업이나 변경 되돌리기를 제공하지 않는다고 명시한다. 설치는 개발 미리보기 단계다.

경쟁 도구 설명서와 공개 코드 검토에 기반하며 설치·동일 실기 시나리오 비교는 수행하지 않았다. 우리 경쟁력 후보는 범위 자체보다 버전 검사·보존본·검증된 복구를 일관되게 제공하는 데 있다. 보안 샌드박스나 완전한 동시 실행 트랜잭션은 아니다.

## 개발 우선순위 판단

1. 사용 목표를 파일 관리에서 실제 실행까지 확장한다면, 검증된 로컬 실행 계층을 재사용하는 방식과 자체 구현 비용을 먼저 비교한다. 새로운 셸 도구를 이번 분석 중 자동 추가하지 않는다.
2. PDF·Word·Excel·이미지를 실제 작업에 쓰려면 형식별 읽기/편집 또는 기존 프로그램을 호출하는 경로가 필요하다.
3. 대용량 분할 쓰기, 검색 이어가기, 해시 검사 비용과 타임아웃을 개선하고 외장 SSD·다른 Mac에서 시험해야 한다.
4. 마지막으로 설치·키 저장·로그인 재연결을 단순화해야 일반 사용자에게 전달 가능한 제품이 된다.

판정 기준은 같은 파일을 같은 ChatGPT 계정에서 처리하는 실제 작업 성공률, 충돌 시 자료 보존, 복구 성공률, 설치 과정, 처리 시간이다. 아직 그 비교를 하지 않았으므로 현재 제품을 가장 좋다고 홍보하지 않는다.
